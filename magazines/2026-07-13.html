Directly applies to you

Unauthenticated RCE in Motorola's MR2600 Router

A researcher chained two authentication bypasses in Motorola’s MR2600 Wi-Fi router to flash arbitrary firmware without any credentials — full remote code execution on an end-of-life device whose auto-update infrastructure is already dead.

The exploit is a small masterclass in how minor logic slips compound. The firmware-upload endpoint validates the SEAMA image by its magic bytes before it checks authentication — and it never deletes the uploaded file when that auth check fails, so the attacker’s payload is already sitting in /tmp/firmware.img. The flashing endpoint then trusts an inconsistent path check: substring matching for the allowlist, but exact matching for the denylisted /WEBCGI1/. Append an allowlisted parameter such as ?Login.html to the request and you slip past both gates at once. No password, no session — just a crafted POST and the box is yours.

Shodan shows only around 41 of these routers directly exposed, so this is not an internet-wide emergency. But the MR2600 is consumer Wi-Fi 5 hardware last patched in mid-2024, and Motorola’s update pipeline is defunct — meaning no fix is coming, ever. That is the real lesson for a security leader: the danger is not this single router, it is the whole class of dead-but-still-deployed edge devices sitting on home-worker networks and in forgotten branch offices, quietly waiting for someone to point a scanner at them.

What to do

Inventory any Motorola MR-series or other end-of-life routers on staff home networks and remote sites. Disable WAN-side remote management, segment the device off trusted VLANs, and schedule replacement with vendor-supported hardware. Treat “no patch will ever ship” as the trigger for decommissioning — not as a reason to keep waiting.

Surveillance & Privacy

Chromium 148 Made Math.tanh a Fingerprint for Your OS

A one-line change in V8 — swapping Chrome’s bundled math library for the host operating system’s — quietly turned Math.tanh into a tell. The very same call now returns three different bit patterns on Windows, macOS and Linux.

Before Chromium 148, V8 computed tanh with its own bundled fdlibm port, so every browser on Earth returned identical bits. Commit c1486295ae5 replaced that with std::tanh, which reads whatever libm the operating system ships — glibc on Linux, libsystem_m on macOS, UCRT on Windows. Because IEEE 754 does not require correctly-rounded transcendental functions, each vendor uses its own polynomial coefficients and lookup tables, and Math.tanh(0.8) now yields a distinguishable value per platform. It is a fingerprinting signal that costs nothing to read and sits well below the radar of most anti-tracking tools.

The sharper consequence is that it breaks spoofing. A privacy tool that rewrites the User-Agent to claim macOS while the machine quietly returns Linux math bits creates a contradiction a fingerprinter can detect — the mismatch itself becomes the signal. Transcendental-function drift now joins canvas, WebGL and audio fingerprinting as another entropy source browsers keep re-introducing by accident whenever they chase native performance. For anyone leaning on anti-detect browsers or fingerprint randomisation to protect research or investigation work, the attack surface just got a little larger.

The State of MCP Security in 2026

A new industry report takes stock of Model Context Protocol security as MCP servers proliferate inside developer and agent workflows — and finds a young ecosystem where convenience has raced far ahead of the controls a security team would expect.

MCP is the plumbing that lets AI agents call external tools — file systems, databases, SaaS APIs, browsers — and it has spread fast precisely because wiring up a new capability is trivially easy. That ease is the problem. A single MCP server often runs with broad, standing credentials; tool descriptions and returned data flow straight into a model’s context, opening the door to indirect prompt injection; and third-party servers are pulled in with the same unquestioning trust the npm ecosystem eventually learned to regret. The report frames these as structural weaknesses, not teething incidents that will simply age out.

For a CISO the uncomfortable part is that MCP adoption happens bottom-up, inside individual engineers’ agent setups, long before governance catches up. The threat model is genuinely new — a poisoned document or web page a tool retrieves can carry instructions that hijack the agent — and traditional allowlisting doesn’t map cleanly onto “an autonomous agent choosing which tool to call next.” This is the shadow-IT of the agent era, and the window to set policy before it becomes load-bearing is closing faster than most programmes realise.

What to do

Build an inventory of the MCP servers running across your engineering org and treat each as a third-party integration: scope credentials to least privilege, sandbox any server that touches untrusted content, and require review before a new server is wired into anything with production reach. Fold agent and tool-injection scenarios into your threat modelling now, while the blast radius is still small.

Claude Code Sends 33K Tokens Before It Reads Your Prompt

A wire-level comparison found Claude Code ships roughly 33,000 tokens of system prompt, tool schemas and injected context on every request — while OpenCode does comparable work in about 7,000. Most of that payload arrives before your actual question does.

The overhead is less waste than a design philosophy made visible. Claude Code front-loads a large system prompt, verbose tool definitions and auto-loaded context — memory files, environment details, git state — so the model rarely has to stop and ask for the basics. OpenCode takes the leaner route, sending far less scaffolding and paying for it with occasional extra round-trips. Prompt caching softens the cost on repeated calls, but the first request in every session, and every cache miss, still carries the full freight. Across a busy day of agentic work, that constant adds up in both latency and spend.

For anyone running these tools at scale — or funding a team that does — the number is worth internalising rather than dismissing. It reframes “why is my bill higher than I expected” as a structural property, not a mystery. It also sharpens the case for trimming what you can actually control: leaner CLAUDE.md files, fewer always-on MCP tools, and disciplined session hygiene all shrink the constant. The tradeoff is genuine capability, so this is tuning, not stripping — but you cannot tune a cost you have never measured.

What to do

Audit your Claude Code setup for avoidable constant overhead — oversized CLAUDE.md files, MCP servers loaded but rarely used, and long-lived sessions that quietly accumulate context. Lean on prompt caching, and where a task is genuinely simple, ask whether a lighter tool or model tier fits. Measure token usage per session before assuming the defaults are optimal for your workload.

AI & Society

Automation Without Understanding

As AI systems begin producing genuine mathematics — including a recent disproof of an Erdős conjecture — this essay argues that letting human mathematical capacity erode at the same moment is a strategic error on the order of losing semiconductor manufacturing.

The argument is not anti-AI; it is about who is left to check the machine. When an AI disproves a long-standing conjecture, someone still has to verify the reasoning, and that ability lives only in a trained human pipeline that takes decades to build and can be defunded in a single budget cycle. The author’s proposal is concrete: treat mathematical capacity as strategic infrastructure, on a par with chip fabrication, and require AI performing consequential reasoning to expose its decision-critical claims in formal, machine-checkable form rather than in fluent, persuasive prose.

That framing travels well beyond mathematics. Any organisation leaning on AI for high-stakes judgement — security triage, legal analysis, financial modelling — faces the same trap: automate the output while quietly losing the in-house expertise needed to challenge it. “Auditable structure rather than persuasion” is a sharp test to carry into procurement and design reviews. The systems worth trusting with consequential decisions are the ones that make their reasoning inspectable, not the ones that are merely convincing.

AI Engineering

Migrating a Production Agent to GPT-5.6: 2.2× Faster, 27% Cheaper

After four months in which Claude Opus dominated their evaluations, one team found GPT-5.6 finally overtook it for building marketing sites end-to-end — but the headline speed and cost wins came from unglamorous engineering, not the model alone.

The raw gain was real: GPT-5.6 wrote dramatically leaner code — 2,508 characters versus 17,957 in one matched pair — halving output tokens and reaching a finished page 2.2× faster at 27% lower cost. But the write-up is honest about how much came from plumbing. Workspace-scoped prompt caching lifted first-call cache hits from near zero to 83.7%, recovering most of the apparent price advantage, and fixing a tool argument-passing bug cut redundant calls by roughly 30%. The model was necessary, but nowhere near sufficient on its own.

The migration notes are the genuinely useful part for anyone weaving models into production. GPT-5.6 invents values for unused tool parameters, so they rewrote optional fields as required-but-nullable and stripped the nulls at the boundary; OpenAI’s caching model differs enough from Anthropic’s that cache keys had to be redesigned; and setting store: false kept reasoning self-contained to avoid mid-conversation failures. The tradeoff: GPT-5.6 drifts toward generic layouts unless firmly steered on brand — a reminder that a model swap is an engineering project, not a config change.

Opinion

I Love LLMs, I Hate Hype

George Hotz stakes out a position that is neither doomer nor booster: LLMs are genuinely useful tools — coding agents, video generation, self-driving — and the singularity narrative wrapped around them is, he argues, a fundraising device dressed up as prophecy.

Hotz separates two kinds of hype he wants no part of. The first is negative hype — the “the window is closing, move to San Francisco or fall behind” narrative he reads as manipulation. The second is singularity hype, the leap from useful tool to superintelligence reshaping reality, on which he offers to bet everything he owns that it won’t happen. His grounding claim is that progress comes from compute and Moore’s Law, not from any lab’s proprietary genius — so the value the labs insist they are creating is not value they will ultimately capture.

Whether or not you take the wager, the essay is a useful corrective for anyone setting strategy amid the noise. Treating LLMs as powerful, improving tools — closer to compilers than to gods — leads to better decisions than either paralysis or messianic bets. Hotz’s sharpest point is about incentives: safety alarmism, he suggests, can double as a moat, because “these are inevitable and commoditising” is a far less fundable story than “only we can be trusted with the fire.” Read the incentives, then read the capability.

Coding Agents

Terry Tao Ports Two Dozen Apps with Coding Agents

The mathematician Terence Tao migrated roughly two dozen legacy Java applets to JavaScript and built several new visualisation tools by “vibe coding” with an AI agent — a working scientist’s field report on where the automation actually lands.

Tao’s account is notable for being unglamorous and precise. Porting old applets took hours rather than days; across two dozen apps the agent introduced only one minor bug, and it caught two bugs that were latent in the original code. He let the agent handle low-level syntax and implementation while he retained the high-level design decisions — reviving, among other things, an abandoned 1999 special-relativity spacetime tool. It is exactly the kind of long-tail, personally motivated software that would otherwise never have been written at all.

His conclusion cuts against both the “coding is dead” and the “AI can’t really code” camps. Domain knowledge remained essential — being able to distinguish the data model from the user interface was what let him get the agent to grasp his intent. The higher-level architecture stayed human; the lower-level friction was automated away. For technical leaders the takeaway is calibration: agents are a force multiplier for people who already know what good looks like, not a substitute for that judgement.

AI Interpretability

Can We Understand How Large Language Models Reason?

A Communications of the ACM feature follows mechanistic-interpretability researchers borrowing tools from causality theory to move past correlation — asking not just which neurons light up, but which internal computations actually cause a model’s output.

Standard interpretability often stops at observation: probe the activations, note that certain features correlate with certain behaviours. Causal methods push harder by intervening — ablating or patching internal components and measuring what changes downstream — to distinguish the circuits that genuinely drive a decision from those merely along for the ride. The payoff, if it matures, is a principled account of model behaviour rather than a gallery of suggestive heatmaps, and a firmer basis for predicting how a system will act well outside its test distribution.

For security and governance this is more than academic curiosity. Interpretability that can say why a model produced an output — and what would have changed it — is the foundation for auditing, red-teaming and incident analysis of AI systems. It is early, painstaking work and nobody should oversell it: today’s techniques scale poorly to frontier models. But it is exactly the “make the reasoning inspectable” capability the rest of this edition keeps circling back to, approached from inside the network rather than from its outputs.

Research & Discovery

AI Speeds Careers but Narrows the Ideas Science Explores

A study across 41.3 million papers finds a quiet paradox: researchers who adopt AI publish three times as much and are cited five times more, yet the collective enterprise converges — clustering ever more tightly around the data-rich problems AI handles best.

The individual incentives are stark and rational. AI-adopting researchers reach leadership roles one to two years earlier, so people follow the gradient — toward well-defined, data-abundant questions where models excel, and away from the messier, sparse territory where the biggest discoveries often hide. Mapped into a high-dimensional “knowledge space,” AI-heavy work shows a smaller intellectual footprint, tighter clustering and weaker follow-on engagement between studies. The danger the authors flag is not slower progress but homogenisation: everyone racing toward the same problems, methods and answers.

The pattern rhymes with a worry threaded through this whole edition — that powerful tools optimise what is easy to measure and quietly starve what isn’t. The proposed fix is not architectural but institutional: restructure the incentives so exploring novel, high-risk questions is rewarded rather than penalised. It is a caution worth holding onto in any field, security included, where the same tooling that makes individuals faster can narrow what the field as a whole even thinks to ask.
